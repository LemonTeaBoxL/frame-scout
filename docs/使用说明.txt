视频巡检 v1.5
创作者：@LemonTeaBoxL
反馈建议：lemonteaboxl@gmail.com

一、运行与项目保存
Windows 10/11 x64，使用系统 .NET Framework 4.8。解压完整文件夹，双击“视频巡检.exe”，保留“引擎”文件夹。
无需 Python 或额外安装视频解码器。视频本地处理，不修改原文件。
自动保存项目已默认开启，记录视频列表、检测结果、审核状态、字幕关联、名词表、已采纳修改、撤销历史及列表布局。正常关闭后，下一次打开会自动恢复。
也可用右上角“保存项目／打开项目”管理独立 .vcheck 项目，保存时保留上一版 .bak。
恢复时核对视频指纹和检测参数；视频、字幕、剧本或规则发生变化的旧结果不会直接当作新结果使用。
项目不包含 API 密钥。API 设置与密钥独立保存在本机，密钥按当前 Windows 用户加密。

二、视频检测（仅夹帧与黑屏）
跳帧检测已取消，新结果只包含“夹帧”和“黑屏”。
支持视频、文件夹及混合拖入，也可手动添加；子文件夹递归查找，同路径去重。
并行线程可选择 1 至本机逻辑处理器数。单个视频使用一个工作线程，解码线程限制为 1。
灵敏度为 0–100，可拖动滑块或填写数字：0 最严格，100 最容易报告疑点。低数值会显著提高画面差异门槛，有助于减少误报，但会漏过较轻微的异常。
夹帧“最多持续”默认 4 帧，可填写 1–3000。这是持续帧数上限；默认覆盖持续一至四帧的突变。
双侧短突变：异常区间与前后画面均有大范围差异，持续时间不超过设置的帧数。
增加“短暂夹入后恢复”的比较：对比异常前、异常中、异常后的画面，识别只夹入一至数帧后恢复的情况；片头另外比较短残留画面与后续连续画面。两类门槛均跟随灵敏度。
单侧突变：只有前侧或后侧出现明显差异时，作为边界候选列为“存疑”。普通切镜也可能触发，不能只凭相邻差异确认整段异常，应看连续帧后人工判断。
比较包含 RGB 颜色差异和发生变化的画面面积，前后差异门槛跟随灵敏度。
“跳过尾部”默认开启，X 默认 60，可取消或自填 0–100000。说明：用于跳过尾部光效结尾的检测。
存在持续尾部黑屏时，从黑屏前的最后一帧有效画面起向前数 X 帧；连续尾黑不占 X。没有尾黑则从视频最后一帧倒数。只跳过夹帧，黑屏仍按自身设置检测。
跨入跳过范围的夹帧候选整体忽略。X 为 0 或关闭开关时不跳过。范围被全部跳过时显示存疑并说明未检查。
黑屏默认只检查片头 15 帧和片尾 15 帧，“检查中间黑屏”默认关闭。
“前后各”可以自行改成其他帧数；勾选“检查中间黑屏”时检查整个视频。边缘填 0 且中间关闭时，不报告黑屏。
“黑屏最短”按秒过滤持续时间；填 0 可以报告单帧黑屏。片头片尾的刻意黑场可人工标为通过。
同一黑场优先报告黑屏，减少重复夹帧提示。

三、列表、单独检测和状态
名称使用自然数字排序，例如 1、2、3、10、11；也支持修改时间、审核状态、检测状态排序及升降序。
时长、分辨率和帧数分别显示为独立列，可以点击列标题或排序菜单排序。时长与总帧数按数值排列；分辨率按像素总量、宽度、高度排列，横竖屏均适用。检测前总帧数带“约”，检测后使用实际解码帧数。
“出现位置”“出现情况”默认隐藏。右键底部状态栏或视频列表，点击“显示 / 隐藏列”，在保持打开的选择面板中勾选开启；列宽、顺序、显隐和分栏位置会随项目保存。
右键菜单可添加视频、添加文件夹、删除此视频（仅从列表移除，保留源文件）、使用默认应用打开。检测期间暂不提供移除。
顶部“重置全部状态”同时重置视频与字幕：保留素材、剧本、名词表、API 和关联，清除检测结果、审核标记、内存中采纳的字幕修改、撤销历史和进度。不会修改原始文件；检测、校对或参考文件加载期间不可重置。
右键某个视频，选择“检测此视频”，只处理该视频；也可以检测选中项目。
绿勾＝通过，红叉＝有错，黄叹号＝存疑。列表及播放窗口均可切换状态，仅作人工审核标记。
重新检测会清除该视频的旧人工标记，完成后按本次实际结果刷新：无异常为绿，夹帧存疑为黄，检出黑屏为红；之后可再次人工判断。
刷新文件夹后，用“检测最新的视频”只处理新加入或发生变化的文件，保留未变化结果。
按大小、修改时间与首中尾抽样指纹识别变化；不是全文件逐字节校验。若只修改了抽样区域之外且保留时间和大小，请选中视频重检。
开始检测前等待文件释放写入占用并连续稳定；超过约 45 秒仍无法读取时提示稍后重试，避免把导出未完成的文件标为通过。

四、定位、播放和对照
点击视频定位首个疑点；点击异常明细或时间线标记定位指定时间。异常标记与播放滑条使用同一实际轨道刻度。
前一帧／后一帧按实际帧时间定位；未检测时依据标称帧率估算。帧号从 1 开始。
上一条视频／下一条视频按当前列表顺序切换，另支持 Ctrl+PageUp／Ctrl+PageDown。
两侧的“上个异常视频／下个异常视频”仅跳转到有检测发现的视频，遵循当前排序；无对应上一项或下一项时禁用，不循环。人工标记通过后仍可跳转到原检测发现，供复查。
支持倍速、播放异常前后、连续帧对照和独立放大窗口。
视频页默认三栏：视频列表、异常列表、视频播放。字幕页默认四栏：每集字幕、名词疑点、当前集 SRT、视频播放。拖动栏间分隔线调整宽度，宽度随项目保存。
异常列表、视频播放，以及字幕页四个面板分别有 ↗ 按钮，可独立悬浮、拖动与缩放。悬浮后的选择、审核与定位仍保持联动。文件列表或预览窗口可以拖入相应素材。
悬浮后的 ↙ 按钮、主界面的“还原窗口”或关闭悬浮窗口，都可还原；关闭主程序同时关闭悬浮窗。播放中切换会保留播放位置并继续。
连续帧窗口展示中心及前后各五帧，点击缩略图放大并同步定位；可在此保存确认正常或异常的校准样本。
独立放大支持适应窗口、100%、放大缩小及全屏；Ctrl+滚轮缩放，Esc退出全屏或关闭。
横屏与竖屏均按比例显示，不裁切；小窗口右侧可滚动查看。
开始播放时先保留当前预览画面，播放器准备并推进画面后再切换，减少加载黑底闪烁。暂停查看会释放播放器文件占用，方便替换。
系统媒体组件不支持连续播放的编码，仍可通过内置引擎定位、逐帧查看。

五、样本校准
先用连续帧窗口标记你确认的正常／异常位置，再打开“样本校准”。至少各有一条有效样本。
比较灵敏度 0、15、30、50、75、100；误报按漏报的两倍计分，取扣分最低、数值较低的档位作为建议。
若所有档位都未命中异常，不给出有效推荐；请检查持续帧数、尾部跳过范围、黑屏范围或补充样本。
校准遵循当前检测类型、持续帧数、尾部跳过和黑屏范围，视频变化后的旧样本不使用。推荐不是质量保证，需要继续用你的实际素材验证。

六、字幕校对与视频关联
进入“检测字幕”，拖入每集 SRT、字幕文件夹，或手动添加。支持 UTF-8、UTF-8 BOM、UTF-16、常见 GBK。
“清空全部”清除字幕列表、校对结果、预览和修改记录，保留剧本、名词表与 API 设置。
优先关联视频界面中的同名视频；视频后添加或刷新时自动补充。也可点“自动关联同名”重新查找，或“手动关联”。
同名／同集出现多个候选时不擅自选择。支持中文与数字集数识别；手动关联在视频仍存在时保留。
字幕预览区有上一集／下一集、定位字幕、播放这条前后、暂停和“视频页打开”。后者会打开关联视频并定位相应字幕时间。
剧本路径框可以直接拖入 DOCX／TXT／MD，也可点“选择…”浏览文件，或粘贴完整路径后按 Enter／点击“加载路径”。成功后显示完整路径。错误路径不会替换已经加载的剧本。旧 DOC 或 PDF 请先另存为 DOCX／TXT。
加载新剧本会使旧名词表、校对结果与内存字幕修改失效，请先保存需要保留的校对版。
在“API 与模型”填写 OpenAI 兼容入口和密钥，自动读取模型列表；支持手动填写模型名和测试连接。
接口可填写 /v1 根地址或完整 chat/completions 地址。服务不支持 /models 时手动填模型名。
可先从剧本提取并审核名词表，或直接开始校对；也可点“导入名词”选择多个文件，或把文件拖到该按钮。导入过程在本机完成，不调用 API。
名词导入支持 TXT、MD、CSV、TSV、JSON、DOCX、RTF；文本自动识别 UTF-8、UTF-16 和常见 GBK。重复标准名词自动合并别称。已有名词保留，导入结果可打开“名词表”审核。
TXT／MD／DOCX／RTF 使用每行或每段一个名词，也支持“标准名词 | 可接受别称 | 类型”。CSV／TSV 可使用表头“标准名词、别称、类型”，支持带引号的逗号内容。JSON 使用 nouns 数组，每项包含 canonical、aliases、category，或直接使用字符串数组。参考“名词导入示例”文件夹。
合法昵称、简称可以放入别称；剧本中找不到的导入词会明确提示缺少出处，请人工核实。
只检查人名、地名、组织及专用词写法，保留实际台词、剧情、语气、标点和普通措辞与剧本的差异。
优先参考对应集的剧本原句；建议显示实际剧本出处。跨集出处会标为存疑；人工词条未找到原句时会明确说明。
点击名词疑点查看对应字幕和视频；“查看出处”可打开剧本原文。

七、字幕多对话、进度和日志
可开启“多对话分批”，自填每组文件数（1–100）及并发对话数（1–16）。默认关闭，默认每组 5 集、并发 2。
开启时提示可能增加 token 用量及费用：独立请求需要重复携带名词表和校对说明；并发数本身不等于费用倍数，实际以服务商用量为准。
顶部进度条显示处理进度，日志记录名词提取、各对话组、逐集完成、失败和停止，可导出或清空日志。日志隐藏密钥。
个别文件失败不阻止其他分组完成。完成进度可以是 100% 同时包含失败，结果与日志会明确显示成功／失败数量。
停止会取消进行中的请求，保留已完成结果；服务商可能已消耗的 token 无法由本程序撤回。

八、采纳、撤销和另存
采纳所选建议只替换对应名词；“采纳确定项”处理当前集红色确定项，黄色存疑留给人工审核。
可撤销采纳，批量采纳可以成组撤销；恢复项目后仍保留最近修改历史。
“修改预览”集中展示真正修改的字幕原文和新文。切换审核状态不会自动修改文本。
“另存校对版 SRT”保留原时间轴、序号和未采纳内容，输出 UTF-8 BOM，不覆盖原文件，同名输出另存版本。
视频、字幕报告支持 CSV／JSON；项目保存比报告更适合继续编辑和复查。

九、边界与存放位置
检测会缩小画面计算，较小局部变化、复杂转场等可能漏报；闪光、正常切镜也可能成为夹帧存疑。结果用于定位复核，不代表视频质量保证。
字幕判断依赖所选模型，建议人工审核。模型无效编号、名词表以外替换、不完整回答不会标为通过。
字幕接口采用本机模拟服务完成流程验证，未调用你的真实 API；真实服务商的连接、模型能力和校对准确率需要在你的配置下确认。
数据位置：%LOCALAPPDATA%\FrameScout
settings.json：设置；api.json：接口设置及加密密钥；last-session.vcheck：自动项目；calibration.json：校准样本。
项目与报告不包含密钥，但包含你保存的剧本、字幕修改和文件路径，请按自己的资料管理习惯保存。
源码位于 Git 仓库，完整便携版位于 GitHub Releases。

升级提示：先正常关闭旧版，再启动新版；两版使用同一份本机设置与自动项目。首次升级 v1.4 会把旧设置／旧项目的夹帧持续上限更新为 4 帧，并使不匹配的新旧检测结果失效；以后手动调整的上限会继续保存。

十、v1.4.1 滚动与分栏操作
右键视频列表或底部状态区域，点击“显示 / 隐藏列”打开独立列选择面板；连续勾选时保持显示，点击“完成”或标题栏关闭按钮结束。
Shift＋鼠标滚轮：内容超出窗口宽度时横向滚动。鼠标应位于需要滚动的表格、字幕正文或可滚动窗口中。
按住鼠标中键并拖动：同时调整横向和纵向位置；松开即停止。
轻点中键后放开：进入自动滚动，移动鼠标控制方向和速度；再点任意鼠标键或按 Esc 退出，切走窗口也会停止。
拖动两栏之间的整条竖向间隙调整宽度；达到最小宽度时停止，不再通过旧的分栏拖动方式处理。松开后继续按比例随窗口伸缩，项目保存分栏比例。
视频播放下方的四个视频导航按钮使用单行等宽布局，随播放栏一起缩放；窄窗口中文字会按可用宽度缩小。

十一、v1.5 资源管理器定位与悬停静帧
右键视频列表，选择“在资源管理器中显示”，打开所在文件夹并选中该视频。文件不存在时尝试打开原文件夹。
视频页和字幕页的播放区都有“▤ 前后15帧”按钮。鼠标悬停后缩略条渐显；移入缩略条时保持显示，离开按钮及缩略条后渐隐。渐隐期间移回鼠标会恢复显示。
点击按钮或缩略条中的“固定”可保持显示；取消固定后恢复移出渐隐。点击缩略图可定位画面。播放时悬停会暂停，以便查看稳定画面。
缩略条包括当前帧以及前后各15帧，共31张；片头片尾只显示实际存在的画面。横屏和竖屏均保持比例，超出宽度时可横向滚动。
已检测视频使用实际帧号与解码时间戳。未检测视频也围绕实际当前画面取帧，但全片帧号会标记为估算；可变帧率视频尤其建议先检测以获得精确帧号。
点击“保存这些静帧…”自行选择文件夹，程序新建独立子文件夹，输出原尺寸PNG，并附“静帧说明.json”记录帧号、实际时间和来源。不会覆盖之前导出的图片。

十二、诊断模式及按帧号查询
顶部“诊断模式”默认关闭。开启后请对目标视频重新检测；开关不追溯已完成的旧检测。
诊断记录程序操作、播放和窗口状态、导入/刷新/项目操作、字幕/API处理进度、FFmpeg输出、检测参数、逐帧差异/变化面积/亮度/黑屏指标、候选判断及过滤原因。API密钥会脱敏，不写入日志。
诊断会增加磁盘写入和占用；记录保留在本机，不自动上传，也不自动删除历史会话。
点“诊断日志”选择当前或历史检测，填写从1开始的帧号，例如157，再点“查看判定依据”。可指定完成、取消或失败的记录；默认优先最近完成的检测。
点“导出全部诊断包…”选择保存位置，导出当前与历史会话的日志ZIP。检测进行中也可导出快照。包内不附视频、剧本、字幕原文件或API配置，但包含本地路径和调试数据。
日志默认目录：%LOCALAPPDATA%\FrameScout\diagnostics
固定入口：%LOCALAPPDATA%\FrameScout\diagnostics\latest.json
每个会话包含session.json、index.json、events-*.jsonl；每个视频记录包含input.json、thresholds.json、frame-metrics.csv、frame-times.csv、decisions.jsonl、analysis.json，失败时有failure.json。
界面帧号从1开始，FrameIndex从0开始；例如界面157帧对应FrameIndex=156。frame-times.csv为实际时间，frame-metrics.csv中的ApproxSeconds只作估算参考。
之后向本机助手询问“2号视频第157帧为什么异常”时，可以直接读取这些文件；也可将导出的诊断包提供给其他环境分析。
